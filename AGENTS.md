## Skill usage policy
For any UI/interaction/visual task: use frontend-design + impeccable +
awwwards-animations during implementation, then anti-ui-slop + ui-radar +
review-animations + find-animation-opportunities to audit the result before
calling the task done.

For copy (form states, error messages, empty states, easter-egg command
responses): use microcopy while writing, antislop-copywriting to audit
afterward. Do not use conversion/marketing-copywriting skills on this
project (e.g. anything framed around hero sections, value props, or CTAs) —
this site's voice is technical/terminal, not sales.

For accessibility: use accessibility for audits, fixing-accessibility to
implement fixes, playwright-visual-testing to baseline the result.

If a task needs a capability not covered by an installed skill, run
find-skills first and report what it found before proceeding with default
judgment.
